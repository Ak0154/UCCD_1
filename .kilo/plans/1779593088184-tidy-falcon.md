## Phase 1: Critical (5 issues) — Runtime crashes and silent failures

### Fix #1 + #5 + #10 + #31: Async pipeline integration (orchestrator.py, complaints.py, telegram_bot.py)

**Root cause:** `run_translation` was converted to `async def`, making it an async LangGraph node. LangGraph auto-detects async nodes, so `pipeline.invoke()` now needs `await`. But `run_pipeline()` calls it synchronously and both callers (`BackgroundTasks`, `threading.Thread`) are sync.

**Fix:** Keep `run_pipeline()` synchronous by using `asyncio.run(pipeline.ainvoke(initial_state))` inside it. This bridges the async graph to sync callers safely.

**Files:**
- `agents/orchestrator.py` line 182: Change `return pipeline.invoke(initial_state)` to `return asyncio.run(pipeline.ainvoke(initial_state))`
- Add `import asyncio` at top of orchestrator.py
- No changes needed in `complaints.py` or `telegram_bot.py` — they continue calling `run_pipeline()` synchronously

### Fix #3: KeyError on failed translation (ai.py, orchestrator.py)

**Root cause:** `translate_preview()` and `run_translation()` directly index `result["translated_text"]`, `result["detected_language"]`, `result["translation_status"]` without try/except around the `await svc.translate()` call.

**Fix:** Wrap `await svc.translate()` in try/except in both callers. On exception, return safe defaults instead of crashing with 500.

**Files:**
- `api/routes/ai.py` lines 24-29: Wrap `await svc.translate()` in try/except, return fallback dict on error
- `agents/orchestrator.py` `run_translation()` lines 27-35: Wrap `await svc.translate()` in try/except, return fallback dict on error

### Fix #4: websocket.py broadcast_event() event loop race

**Root cause:** `broadcast_event()` called from APScheduler thread (which runs in a thread pool) can hit `RuntimeError: event loop already running` on `asyncio.run()`.

**Fix:** Use a thread-safe queue + background worker pattern. Replace `broadcast_event()` sync function with a `queue.put_nowait()` approach and have a dedicated asyncio task consume the queue. Or simpler: check if there's a running loop AND if it's not already running (use `asyncio.get_event_loop().is_running()` safely).

**Simpler fix for now:** Replace the `asyncio.run()` fallback with `loop.run_until_complete()` using the main thread's loop only (store it at startup). Add a dedicated `_main_loop` reference set during app startup.

**Files:**
- `api/websocket.py`: Refactor `broadcast_event()` to use a stored loop reference from startup
- `api/main.py`: Store the running loop during lifespan startup

### Fix #2: telegram_bot.py called synchronously from async lifespan() (main.py)

**Current state:** `start_telegram_bot()` just spawns a daemon thread — no blocking I/O, so it's safe. The report notes it's "structurally fragile."

**Fix:** Document this is intentional (thread-only, no I/O). No code change needed, but add a comment in `api/main.py` at line 25 explaining this.
